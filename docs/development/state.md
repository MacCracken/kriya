**1.5.1** — released 2026-08-26. **`ls -t` / `-S`, and the sort stops being quadratic.** ⭐ **Both keys sort DESCENDING with a NAME tie-break**, measured not assumed. ⚠ **`-t` compares NANOSECONDS**, not just seconds — two files one nanosecond apart sort correctly in GNU, so comparing `st_mtime` alone would be a silent wrong order on any sub-second filesystem; the tie test FORCES an exact tie with `touch -d` rather than hoping two files collide. ⭐ **Every key falls through to the name comparison**, which makes the order TOTAL — two distinct entries never compare equal, so `-r` is a true reversal rather than a stable-sort artefact (verified: an exact-mtime tie gives `a m z` under `-t` and `z m a` under `-tr`). ⛔ **With BOTH `-t` and `-S`, the RIGHTMOST wins** — `ls -tS` is a size sort and `ls -St` a time sort — and `flags_get_bool` cannot answer that (it says 'was it given', not 'which came last'), so `ls` scans argv for the order, clusters included; ⚠ the smoke test asserts the two forms DISAGREE WITH EACH OTHER, since a pair that both resolved the same way would pass while proving nothing. ⛔ **The sort was O(n²) and it showed**: 8,000 entries took **0.755 s against GNU's 0.004 s, a 190× gap** on a directory size that is not unusual. A bottom-up merge sort takes it to **0.022 s (34× better)**, closing the gap to ~5×. ⚠ Restructuring the comparator for `-t`/`-S` was required anyway, and leaving a quadratic sort inside the release that is ABOUT sorting would have been an odd place to draw the line. ⛔ **Two sort defects were found AFTER this release was first reported green.** (1) **A sort flag AFTER the operands was silently dropped, and this release INTRODUCED it**: `ls -1 aa bb cc -rt` honoured the `-r` and dropped the `-t` from the SAME cluster, giving name order with exit 0 and empty stderr — `_ls_scan_sortkey` bounded itself with `kriya_argv_option_end`, which stops at the first operand, while the PARSER permutes. ⭐ **The fix was to stop having a second option window, not to widen it**: kriya's parser already produces a normalised EXPANDED argv (clusters split, long forms normalised, `--` honoured), so `kriya_short_seq` asks the parser and `ls` compares two integers; widening the scan would have re-created the bug at the next value-taking option, since `ls -w -t` must not read `-t` as a flag the parser consumed as the width. ⚠ **Every existing assertion put the flags FIRST**, so none could have caught it. **1.4.5** — released 2026-08-26. **The `-i` bracket-class quirk; 1.4.x closes.** ⛔ **`kriya grep -i '[[:upper:]]' ` returned NOTHING where GNU returns every alphabetic line**, with no diagnostic — the last item on the arc, carried since the M7 POSIX audit. ⭐ **The cause is one sentence and it generalises: a bracket expression is not a byte, it is a SET, and lower-casing its source TEXT does not lower-case the set it denotes.** `-i` folds the SUBJECT to lower case and folded the pattern alongside it — right for literal bytes, and a no-op on `[[:upper:]]`, whose text is already lower case, so the class survived intact and could never fire. ⚠ `[[:lower:]]` was **accidentally** correct, which is why the bug reads as one broken class rather than a broken mechanism. ⭐ **GNU's real rule, measured**: `[:upper:]` and `[:lower:]` BOTH become `[:alpha:]` (⚠ not 'match everything' — digits and punctuation still do not match, and a fixture without them cannot tell those readings apart); a range `x-y` is an ERROR iff `toupper(x) > toupper(y)`; otherwise if `x > y` raw it matches NOTHING and is NOT an error; otherwise the RAW span is kept plus every member's counterpart, so `[A-z]` still covers the punctuation between `Z` and `a`. ⛔ **The error gate is the UPPER-case fold and that is load-bearing**: `[A-_]` is accepted and `[B-a]` refused though BOTH have a reversed lower-case fold — a lower-case gate fits most of the data and gets exactly those wrong. ⭐ **Verified by brute force: 41,868 range comparisons, zero divergences** — all 8,281 printable-endpoint ranges in grep's BRE and ERE engines with `-i` AND without, plus all 7,744 in `find -iregex`, plus 5,000 randomised bracket patterns — ⚠ three earlier models passed every hand-picked example and died on the sweep. ⛔ **Two traps in the ORACLE, either of which would have taught the wrong fix.** (1) **The rule is LOCALE-DEPENDENT**: `grep -i '[>-a]'` gives THREE different answers under `C`, `C.UTF-8` and `en_US.UTF-8`, because a bracket range walks COLLATION order, not byte order — an early pass produced a model fitting nothing purely because the ambient locale was not what it looked like. kriya is byte-ordered and ASCII-only by design (ADR 0005), so it implements the C-locale rule and every comparison pins `LC_ALL=C`. **1.2.4** — released 2026-08-25. **Destructive-verb semantics (ADR-gated).** Fifth batch of the 1.2.x arc — two cases where a destructive verb destroyed data and THEN reported failure. Both were behaviour decisions, so each got an ADR: **0009** and **0010**, with ADR 0003's status updated to record that 0010 extends it. ⛔ **`mv` deleted the only surviving copy.** Cross-FS `mv` is copy-then-remove, and it rolled the destination back when EITHER step failed. ## Role

Coreutils-equivalent for AGNOS — the small POSIX-style utilities (`cp`, `mv`, `rm`, `mkdir`, `echo`, `wc`, `find`, `grep` …) in one repo, sharing a `src/lib/` of path / errno / argument-parsing primitives. Each utility is a separate command (via symlink → dispatcher). Sovereign-replacement boundaries documented in `CLAUDE.md` (owl owns `cat`, sit owns `git`, chakshu owns `htop`, cyim owns `vim`, agnoshi owns shell builtins — kriya fills the gaps).

### Post-1.0 — sequenced in roadmap.md

[`roadmap.md`](roadmap.md) is **open work only** — shipped milestones were removed at v1.2.5, because
the record of what landed belongs in `CHANGELOG.md` and here, not in a plan. It sequences the
remaining work into **arcs batched by shared enabler**: shipping the enabler *is* the release, and one
round of test work then serves the whole batch.

**The 1.2.x correctness arc is closed** — 1.2.0 option handling, 1.2.1 accepts-and-lies, 1.2.2 the
spawn helper, 1.2.3 walk safety, 1.2.4 destructive-verb semantics, 1.2.5 the chrono batch, 1.2.6 the
last three P-1 defects. **All ten M17 defects are fixed and the bucket is retired.**

⭐ **Four arcs are now closed**: 1.2.x correctness, **1.3.x discoverability** (`--help`,
`--help=json`, `kriya --list`, `--version`, and a CI that can fail), **1.4.x pattern & text parity**
(grep context, shared glob, multibyte `cut`, `uniq --group`, `nl` sections, `echo -e`, the `-i`
bracket quirk) and **1.5.x identity & listing** (passwd/group, `ls` sort keys, `--color`, quoting).
Each closed section in `roadmap.md` keeps only its NON-GOALS, its still-open leftovers and its
carry-forward lessons — the account of what shipped lives in `CHANGELOG.md` and in the version
entries above.

⚠ **The next arc is 1.6.x (file-op completeness)**, gated on an inode-set helper in `src/lib/fs.cyr`
and an fd-anchored xattr API. ⛔ Nothing blocks it: the arcs are independent by construction and can
be resequenced by consumer demand. **1.5.4** is a small optional cleanup pass over the `ls`/`stat`
output leftovers if a consumer asks for them first.

⚠ Everything below is **new capability rather than defect repair** — a different kind of risk. These
change what kriya *does*, not what it gets wrong, so expect more ADRs and more GNU-comparison work per
item than 1.2.x needed.
