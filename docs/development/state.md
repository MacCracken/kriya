## Version

**1.2.3** — released 2026-08-25. **Walk safety.** Fourth batch of the 1.2.x arc — two recursive walks that were not doing what the rest of kriya does. ⛔ **`grep -r` descended BY PATH, not from a parent fd** — every level re-opened the accumulated path with `openat(AT_FDCWD, …)`, re-resolving every ancestor, so a directory swapped for a symlink to `/etc` mid-walk redirects the walk out of the tree. The per-file `O_NOFOLLOW` from the M8 audit was no defence: it guards the FINAL component only, and made the walk look protected. `rm`/`cp`/`find` have descended from a parent fd since M2 (ADR 0003); grep was the last path-based walk. ⭐ Proven with a **tree deeper than PATH_MAX** — no race needed, because a path-based descent physically cannot open a 6 KB path: before, `file name too long` at depth 14 and nothing found; after, the needle at depth 500, byte-identical to GNU. So it is also a user-visible fix — `grep -r` now works on deep trees. ⚠ agnos needed a different shape: `fs_opendir_nofollow(real_dirfd, …)` is `-ENOSYS` there, so a naive dirfd rewrite would have broken `grep -r` at depth 1 on the target kriya exists for. New `fs_open_entry_dir`/`fs_open_entry_file` take both the dirfd and the full path, following the `fs_stat_entry` precedent. ⛔ **`cp -i -R` overwrote without a single prompt** (verified under a real pty; GNU asks) — `interactive` was never threaded through `_cp_dir_top` → `_cp_dir_descend_at` → `_cp_file_at`. And **`cp -R` with no `-f` silently replaced existing files** while the non-recursive path immediately above it has always refused that: cp was inconsistent with itself, and the recursive half was the one contradicting CLAUDE.md's "no silent overwrites without -f". Both now refuse. ⚠ A deliberate GNU divergence — being consistently stricter beats being inconsistently permissive on a destructive verb. **A declined prompt is now exit 1** (GNU parity); kriya returned 0, so `cp -i … && next` proceeded on a refused copy. **1243 smoke cases across 33 scripts** (up from 1230), 119 unit + 18 POSIX, 1529 fuzz green under poison.

**1.2.2** — released 2026-08-25. **The spawn helper: children can speak again.** Third batch of the 1.2.x arc — a kriya-local fork + execve + waitpid in `src/lib/spawn.cyr`, replacing stdlib `exec_env` for the two utilities that run user-named commands. ⛔ **`find rot -name '*.tmp' -exec rm {} \;` on an unwritable directory printed NOTHING and exited 0** while deleting nothing; GNU prints a Permission-denied line per file. The cause is one stdlib line — `exec_env`'s Linux arm dup2s `/dev/null` onto **fd 2** before exec, so every child diagnostic vanished. kriya now simply does not touch fds 0/1/2, and that omission is the whole fix. ⛔ **Two rungs of the POSIX exit ladder were wrong** because `exec_env` collapses every non-exit outcome to -1: a signalled child reported **127 (should be 125)** and a non-executable one **123 (should be 126)**. ⭐ A **CLOEXEC pipe** is what makes "exec failed" distinguishable from "child exited with that status" — the child writes its errno through, and a successful execve closes it silently; no exit-code convention can express that. ⛔ **xargs kept going after a catastrophic failure** — POSIX says exit-255 aborts the invocation; kriya ran all three items where GNU ran one. Both loops now abort on 124/125 and emit GNU's diagnostics; a plain nonzero still continues. ⚠ agnos has no fork (only `execwait`, no argv/envp/fd control), so that arm delegates to `exec_vec` and reports an exit status only — the stderr half of the bug was Linux-only, the ladder half was not. ⭐ Unblocks `find -exec ... +`, `xargs -P` and `xargs -p`, all of which need a spawn primitive returning more than an exit code. **1230 smoke cases across 33 scripts** (up from 1215), 119 unit + 18 POSIX, 1529 fuzz green under poison.

**1.2.1** — released 2026-08-25. **Accepts-and-lies.** Second batch of the 1.2.x arc, and not a feature release: every change is a place kriya returned **success while doing the wrong thing**. The class turned out wider than the roadmap had it — two items catalogued, six shipped. ⛔ **Every bool long option silently swallowed `=VALUE`** — `sort --reverse=nonsense` sorted and exited 0, as did `rm --force=`, `grep --count=`, `wc --lines=`, `ls --all=`, across all 28 utilities on the shared parser. Now refused with GNU's own diagnostic naming the option. ⚠ Three options legitimately take a value and are handled explicitly, since the parser cannot represent an optional-value long: **`cp --preserve=LIST`** (honours `mode`/`timestamps`, refuses `links`/`ownership`/`all` **by name** rather than ignoring them — `--preserve=links` used to exit 0 while turning hard links into independent copies), **`sort --check=quiet`** (now actually suppresses the disorder line), **`tail --follow=name|descriptor`**. ⛔ **`grep -e A -e B` matched only the last pattern** — the spec has one value slot, so earlier patterns were overwritten with no diagnostic; grep's matcher was always multi-pattern (that is how `-f` works), only the collection was lossy. New `kriya_argv_collect` walks the expanded argv so every spelling normalises. ⛔ **`printf '%f' 1.5` printed the letter `f` and exited 0** — warned on stderr, wrote the bare conversion char to stdout dropping the `%`, reported success. Now exits 1 with nothing on stdout, floats named as a kriya gap rather than a typo, and processing stops at the error like GNU. **`\xHH` implemented** (it had been printing a literal `x41`). ⛔ **`stat -c %y` printed the two bytes `%y`** where a timestamp belonged, exit 0 — same for `%x %z %U %G %N %w` and `date +%V %c %x %X %r %q %G %g`. Now refused by name with a pointer at the milestone that will render them. ⚠ Genuinely unknown specifiers still pass through, but the two differ and the old code had `stat` wrong: `date +%@` → `%@` (matches GNU), `stat -c %q` → `?` (**which is what GNU does**) — and `smoke-stat.sh` had a case pinning the mistake, corrected here. **1215 smoke cases across 33 scripts** (up from 1131), 119 unit + 18 POSIX, 1529 fuzz green under poison.

**1.2.0** — released 2026-08-25. **Option handling: `rm -rf` works.** Opens the **1.2.x arc**, which puts a running order on post-1.0 work by batching it around shared enablers rather than by utility; this is the first batch. ⛔ **`rm -rf` used to exit 2** — and so did `ls -la`, `grep -in`, `wc -lw`, `sort -rn`, `cp -rp`, `uniq -cd`, `tail -n5` and `cut -c1-3`. The stdlib parser puts clustered shorts and attached short values explicitly out of scope, so kriya now **pre-expands them** in `src/lib/args.cyr` before handing argv over: `-rf` → `-r -f`, `-n5` → `-n 5`, serving all 28 utilities that route through `kriya_args_parse`. ⭐ The expansion is **spec-driven** — it asks each utility's own flags spec whether a letter is a bool or takes a value, so there is no per-utility table to drift. Also the obsolescent bare-digit form (`head -5`, `tail -3`), unambiguous only because neither registers a digit as a short. ⚠ Eleven utilities are deliberately untouched (`find`, `seq`, `env`, `du`, `df`, `date`, `echo`, `sleep`, `yes`, `true`, `false`) because they walk argv themselves — which is exactly why `find -name`, `seq -5` and `du -sh` keep working. Plus the two M17 defects living in the same code: ⛔ **`xargs` was parsing the child's command line as its own** (`xargs sort -r` silently sorted ascending; `xargs head -n 2` ran head with no options; and the **`--` guard was consumed and deleted**, so `ls -1 | xargs rm --` recursively deleted what `--` protected), and ⛔ **`xargs -I` split on blanks instead of lines** (`printf 'a b\n' | xargs -I{} rm -- {}` deleted files `a` and `b` and left `a b`). Both verified against GNU. Two stale source comments corrected: `tail -f` shipped at v0.5.0 and `sort -k F1,F2` works — both were still listed as deferred. ⛔ **New organising rule: "accepts and lies" outranks "rejects cleanly."** Auditing the deferred markers found two cases where kriya returns success while doing the wrong thing — `grep -e A -e B` silently uses only the last pattern, and `cp --preserve=links` is accepted and ignored — both pulled forward into **1.2.1**. **1131 smoke cases across 33 scripts** (up from 1081/32) including a new `smoke-option-forms.sh` that pins both what must now be accepted and what must still be left alone; 119 unit + 18 POSIX; 1529 fuzz assertions green under poison.

**1.1.11** — released 2026-08-25. **The P-1 sweep: nine repairs, six of them data loss, corruption or disclosure.** A priority-one audit across security, hardening, correctness, refactor and performance; no new utilities or flags — every change stops an existing verb doing something wrong. Each defect was reproduced against a shipped build and re-verified against GNU. ⛔ **A failed write used to exit 0 in every applet** — `seq 1 5 >/dev/full` printed nothing and succeeded, because v1.1.8 routed all writes through `k_write` without making any of the ~540 call sites check the result; `k_write` now records the first failure and the dispatcher consults it once at exit (and the Linux arm stopped dropping short writes, which the agnos arm already retried). ⛔ **`k_access`'s agnos arm smashed 96 bytes of its own frame** — `var st[48]` for a buffer `_k_agnos_stat` always fills with the canonical 144-byte layout; the M15a function-local-`var X[N]`-is-N-*bytes* rule biting for the second time in three releases, reproduced on the host as a SIGSEGV. ⛔ **`cp -r dir dir/sub` recursed until it dumped core** — 12,188 directories created before the crash; now refused before anything is created, where GNU leaves two levels behind. ⛔ **`rm -r parent/sub/..` emptied the parent** and then reported "no such file or directory"; POSIX requires the refusal and GNU refuses even under `-f`. ⛔ **`ln -f` deleted the destination when it could not create the link** — now link-to-temp-then-rename, because the tempting "unlink only on EEXIST" shortcut fails: the kernel reports EEXIST *before* EXDEV. ⛔ **An unset `PATH` ran a binary from the CWD** in `xargs` and `find -exec` (`execve` does no path search); unset now falls back to `/bin:/usr/bin` and a failed search exits 127 — the two utilities had byte-identical 45-line copies of the resolver, now one `fs_resolve_in_path`. ⛔ **`find -exec` leaked adjacent heap into the child's argv** — the `{}` buffer assumed at most four occurrences; a fifth spilled kriya's cached PATH string into the argument. ⛔ **`realpath` silently answered the wrong path past 16 KiB** — `fs_realpath`'s seed and symlink-rebuild copies were unchecked; now `ENAMETOOLONG` (kriya therefore refuses inputs GNU still resolves — M17j). ⛔ **The ADR-0004 root guard failed open** when `getcwd` failed (cwd > 4095 bytes); now fails closed. **137 in-process assertions** (119 unit + 18 POSIX, up from 104) and **1081 smoke cases across 32 scripts** (up from 1012/31) — including 21 unit assertions pinning every spelling of `/` the root guard must refuse, which is the only safe way to test it. ⚠ **Ten further defects were confirmed and deliberately NOT fixed** — each needs a redesign, not a patch — and are itemised with reproductions under roadmap **M17**; three reported findings were refuted and recorded in the CHANGELOG so they are not re-litigated. Roadmap reorganised: new standing **M15** codegen watchlist, **M17** deferred defects, and **M16** renumbered from a colliding second M11.

## Role

Coreutils-equivalent for AGNOS — the small POSIX-style utilities (`cp`, `mv`, `rm`, `mkdir`, `echo`, `wc`, `find`, `grep` …) in one repo, sharing a `src/lib/` of path / errno / argument-parsing primitives. Each utility is a separate command (via symlink → dispatcher). Sovereign-replacement boundaries documented in `CLAUDE.md` (owl owns `cat`, sit owns `git`, chakshu owns `htop`, cyim owns `vim`, agnoshi owns shell builtins — kriya fills the gaps).

### Post-1.0 — sequenced in roadmap.md

Post-1.0 work is tracked two ways in [`roadmap.md`](roadmap.md), and both matter:

- **The 1.2.x arc** — the running order. Batched by shared enabler, because half the open work is
  gated on a handful of capabilities and shipping the enabler *is* the release. **1.2.0 (option handling),
  1.2.1 (accepts-and-lies), 1.2.2 (the spawn helper) and 1.2.3 (walk safety) shipped**; next
  1.2.4 destructive-verb semantics (ADR-gated), then 1.2.5 the chrono batch. The roadmap carries an
  **enabler map** naming what each unblocks.
- **Milestone buckets M10–M17** — the catalogue. Every known item, grouped by kind. Summary:

- **M10 — Consumer-burn** — the last v1.0 criterion. Trigger: AGNOS USB-keyboard-on-boot resolves → AGNOS coreutils integration → first green boot-burn → 1.0.1 with consumer-burn audit. Parallel signal on the kernel team's timeline, not a blocker.
- **M11 — Cyrius proposal sweeps** — octal-literal cleanup, raw-syscall → stdlib-wrapper cleanup. Triggered by upstream Cyrius acceptance.
- **M12 — POSIX-deviation fill-in** — GNU-parity features grouped by enabler dependency (chrono, flags, stdlib helpers, per-utility independent).
- **M13 — Performance optimization** — `wc -c` short-circuit, niyama Boyer-Moore, `tail` seek-from-end, speculative items.
- **M14 — stdlib `getenv` post-fork bug** — upstream Cyrius fix; kriya then strips PATH-cache workaround.
- **M15 — Codegen / toolchain-interaction watchlist** *(standing, opened v1.1.11)* — the ways the Cyrius compiler and kriya interact badly, each entry with a mechanical detection and the incident that motivated it. Never closes; re-run the detections at every pin bump. Headline entry: a function-local `var X[N]` is N **bytes** while module scope is N×8 — the rule behind the v1.1.9 `find` smash and the v1.1.11 `k_access` one.
- **M16 — AGNOS as a build target** *(renumbered from M11 at v1.1.11 — the number was already taken by the Cyrius proposal sweeps)* — make `src/lib/fs.cyr`'s syscall layer target-aware, then gate the per-command stragglers.
- **M17 — Confirmed defects deferred from the v1.1.11 P-1 sweep** *(opened v1.1.11)* — ten defects, each reproduced against a shipped build and each needing a redesign rather than a patch: `find -exec`/`xargs` swallowing the child's stderr, `xargs` parsing the child's options as its own (and eating `--`), `xargs -I` splitting on blanks instead of lines, `grep -r` walking from AT_FDCWD instead of a parent dirfd, `mv` cross-FS rollback deleting the only surviving copy, `cp -R -i` never prompting, `ls -l` fabricating metadata on stat failure, grep's per-byte heap retention, the `rm -r symlink/` policy question, and realpath's new 16 KiB ceiling.

Each can advance independently against a tagged 1.x.y minor.
